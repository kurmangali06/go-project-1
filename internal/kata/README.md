# Ката: учимся писать тесты

Восемь уровней по нарастающей. В каждом файле лежит функция с описанным
**контрактом** в комментарии — и с ошибкой, которая этот контракт нарушает.

## Правила

1. Читаешь контракт в комментарии, **не** ищешь баг глазами в коде.
2. Пишешь тест по контракту — так, как будто код правильный.
3. `go test -race ./internal/kata/` → тест **падает**. Значит поймал.
4. Только теперь смотришь в код и чинишь его.
5. Тест зеленеет.
6. Сломай код ещё раз по-другому — тест должен снова упасть.

Шаг 6 не пропускай. Тест, который ни разу не падал, ничего не доказывает.

Порядок важен: пункт 2 до пункта 4. Если сначала посмотреть на реализацию,
тест получится под неё подогнанным, а не под контракт — это самая частая
ошибка при написании тестов задним числом.

## Уровни

| # | Файл | Навык |
|---|---|---|
| 1 | `level1_discount.go` | простая проверка значения, граничные случаи |
| 2 | `level2_parse.go` | табличный тест, `t.Run`, подтесты |
| 3 | `level3_errors.go` | `errors.Is`, обёртки `%w`, sentinel-ошибки |
| 4 | `level4_stock.go` | побочные эффекты: проверять состояние, а не только `err` |
| 5 | `level5_handler.go` | `httptest.NewRecorder`, статусы, заголовки, тело |
| 6 | `level6_client.go` | `httptest.NewServer` — тестируем HTTP-клиент без сети |
| 7 | `level7_counter.go` | `-race`, `sync.WaitGroup`, гонки данных |
| 8 | `level8_context.go` | `context`, отмена, дедлайны, проверка времени |

Файлы тестов называй `levelN_*_test.go`, пакет — `kata`.

## Команды

```
go test ./internal/kata/            быстрый прогон
go test -race ./internal/kata/      с детектором гонок (обязательно для 7)
go test -v -run TestDiscount ./internal/kata/    один тест
go test -count=20 ./internal/kata/  двадцать раз — для нестабильных
go test -cover ./internal/kata/     покрытие
```

## Пока катa не решена

`make check` и pre-commit хук будут падать на этом пакете — это ожидаемо и
правильно. Коммить незаконченную кату через `git commit --no-verify`.

## Подсказки

Каждый уровень решается без внешних библиотек, только стандартной
`testing` + `net/http/httptest`. Если тянет добавить зависимость — значит
задача понята сложнее, чем она есть.
